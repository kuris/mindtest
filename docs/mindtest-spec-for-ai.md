## 1. 반드시 지킬 제약 (위반 시 재작업)

1. **외부 프레임워크·빌드 도구 금지** — React/Vue/Tailwind/번들러 없이 순수 HTML/CSS/JS.
   CDN 허용 범위: 웹폰트(구글 폰트)만.
2. **결과는 반드시 개별 정적 HTML 파일** — JS로 결과를 같은 페이지에 그리지 말 것.
   이유: 카톡 공유 시 결과별 OG 미리보기가 떠야 하고, 결과 페이지가 검색 노출 단위임.
3. **MBTI라는 단어와 공식 문항 사용 금지** (상표·저작권). E/I·S/N 같은 축 명칭도 금지.
   16유형 "구조"만 차용하고 축·문항·유형명은 전부 창작할 것.
4. **"결과를 보려면 광고를 보라" 류의 강제 삽입 금지** (애드센스 정책 위반 소지).
5. 모든 페이지에 `<link rel="canonical">`, 고유한 `<title>`·`<meta name="description">`.
6. 강제 언어 리다이렉트 금지 (향후 다국어 확장 대비 — 크롤러 차단 문제).

## 3. 공통 UI 사양

- 질문은 **한 화면에 하나씩**. 상단 진행바(현재/전체), 뒤로가기 버튼.
- 선택지를 누르면 자동으로 다음 질문 (별도 "다음" 버튼 없음).
- 마지막 질문 후 계산 → `location.href = 'result/<파일>.html'` 로 이동.
- 결과 페이지 구성(위→아래): 결과명(큰 글씨) → 캐릭터 이모지 → 설명 3~4문장 →
  특징 리스트 → 공유 버튼(링크 복사 / 카카오톡 / X) → "다른 테스트 하기" →
  "테스트 다시 하기".
- 공유는 SDK 없이 URL 스킴만:
  - 링크 복사: `navigator.clipboard.writeText(location.href)`
  - X: `https://twitter.com/intent/tweet?text=<인코딩된 문구>&url=<결과URL>`
  - 카카오는 SDK 필요하므로 v1에서는 "링크 복사" 안내로 대체.
- 결과 페이지의 OG 태그 (페이지마다 개별 값):
  ```html
  <meta property="og:title" content="나는 [결과명]! - [테스트명]">
  <meta property="og:description" content="[결과 한 줄 요약]">
  <meta property="og:image" content="https://mind.chatgpts.kr/og/[slug].png">
  <meta property="og:url" content="https://mind.chatgpts.kr/result/[파일명]">
  ```
  (OG 이미지 파일 제작은 별도 작업 — 태그만 먼저 심어 둘 것)

## 4. 데이터 스키마 (전 테스트 공통 패턴)

```js
// data-love.js 예시 — window 전역으로 노출
const LOVE_TEST = {
  id: 'love',
  title: '연애 스타일 테스트',
  axes: ['expr', 'speed', 'dist', 'real'],   // 4축, 각 축은 두 극 (예: expr: E/H)
  questions: [
    {
      q: '썸 타는 사람에게서 연락이 안 온다. 나는?',
      a: [
        { text: '먼저 연락한다. 궁금한 건 못 참아', score: { expr: +1 } },
        { text: '올 때까지 기다린다. 조급해 보이기 싫다', score: { expr: -1 } }
      ]
    },
    // ... 12문항 (축당 3문항)
  ],
  results: {
    // 4축 부호 조합 16가지. key는 각 축의 +/- 조합
    '++++': { slug: 'sunshine-rusher', name: '직진 햇살형', emoji: '☀️',
              desc: '...', traits: ['...', '...'], match: 'shy-turtle' },
    // ... 16개
  }
};
```

- 점수형(kkondae): `questions[].a[].score`가 숫자 하나, `grades: [{min, max, name, pct...}]` 5구간.
- 퀴즈형(vocab): `questions[].a` 중 `correct: true` 하나, `levels`로 점수→급수 매핑.

## 5. 테스트 3종 콘텐츠 요구사항

### ① 연애 스타일 테스트 (16유형)
- 12문항, 4축(축당 3문항). 축은 창작: 예) 표현(직진/신중), 속도(불꽃/뭉근),
  거리감(껌딱지/각자시간), 현실감(낭만/실용) — 명칭은 자유롭게 더 낫게 지어도 됨.
- **유형명이 이 테스트의 핵심 상품이다.** "직진 햇살형", "츤데레 장인",
  "연락 집착러"처럼 친구에게 보여주고 싶어지는 밈형 한국어 이름으로.
  각 유형에 "잘 맞는 유형" 1개를 지정해 결과에 표시(궁합 재미 요소).
- 문항 톤: 카톡·썸·데이트 등 구체적 상황 제시형. 교과서식 문장 금지.

### ② 꼰대력 테스트 (점수 %)
- 10문항, 각 문항 선택지 3개(0/1/2점). 총점 0~20 → 백분율 환산.
- 5등급 예: 0~19% 청정수 / 20~39% 새싹 꼰대 / 40~59% 반반 꼰대 /
  60~79% 프로 꼰대 / 80%~ 화석. (명칭 개선 자유)
- 결과에 인증 문구 노출: "나 꼰대력 73%, 프로 꼰대 ㅋㅋ" + 복사 버튼.
- 문항 톤: 회사·단톡방·회식 상황. 자학 개그로 웃기되 특정 세대 비하는 금지.

### ③ 한자어 어휘력 테스트 (급수)
- 10문항 4지선다. "다음 중 '심심(甚深)한 사과'의 '심심'의 뜻은?" 같은
  한자어 의미 판별 문제. 문항은 실제 한자능력검정 급수 어휘 수준을 참고해 창작.
- 결과 6단계: 8급(입문)~준4급~4급 이상 등. 각 결과에
  **"이 급수 한자 공부하러 가기" 버튼 → `https://hanja.chatgpts.kr/grade.html` 링크 필수**
  (자매 사이트 연결이 이 테스트의 존재 이유).
- 참고: 발주자가 급수별 한자 데이터 파일(`grade-data.js`, 3,500자)을 제공할 수 있음.
  제공받으면 그 데이터에서 출제할 것.

## 6. 디자인 가이드

- 밝고 캐주얼. 파스텔 배경 + 카드형 레이아웃 + 큰 이모지.
- 폰트: 구글 폰트 'Gowun Dodum' 또는 'Noto Sans KR'.
- 색: 테스트마다 키 컬러 1개 (연애=코럴, 꼰대력=네이비, 어휘력=그린 계열 권장).
- 버튼·카드 모서리 크게(16px+), 터치 타깃 최소 44px.
- 다크모드 대응 불필요(v1), 대신 `prefers-color-scheme` 깨지지 않게 배경·글자색 명시.
